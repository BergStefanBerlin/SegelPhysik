# v0.3a - Echtzeit-Visualisierung (Taichi/GPU + PyVista)

Ziel: die Simulation **fluessig und interaktiv** machen. Die Physik bleibt
unveraendert (Spec 1.0); es kommen zwei austauschbare Backends dazu.

## 1. Installation

```powershell
pip install taichi-forge   # Taichi mit Vulkan fuer Windows/Python 3.10-3.14
pip install pyvista
```

Ohne `taichi-forge` laeuft alles weiter mit der NumPy-Referenz
(automatischer Fallback, keine Fehlermeldung).

## 2. Starten

```powershell
python gui.py                    # Taichi (Vulkan) + PyVista, 8x8-m-Becken
python gui.py --backend numpy    # NumPy-Referenz zum Vergleich
python gui.py --full             # Default-Becken 10x10x3 m (langsamer)
```

| Taste | Wirkung |
|---|---|
| `g` / `G` | Gravitation +1 / -1 m/s^2 |
| `w` / `W` | Wind +1 / -1 m/s |
| `Leertaste` | Pause |
| `r` | Reset |
| `s` | Kugel einspawnen |
| `q` | Ende |

Maus: drehen (links), zoomen (Scroll), verschieben (Mitte/Shift+links).

## 4. Design-Entscheidungen

**Backend:** Vulkan (die Radeon 760M hat kein CUDA). `ti.init(arch=ti.vulkan)`
mit automatischem CPU-Fallback. Das offizielle `taichi`-Paket unterstuetzt
Python bis 3.10; fuer 3.11-3.14 liefert `taichi-forge` Windows-Wheels mit
Vulkan/OpenGL/CUDA/LLVM.

**Wandbehandlung:** statische Wand-Partikel (Standard-Boundary-Methode)
statt Spiegel-Geister - deterministisch, GPU-freundlich und ohne die
O(N^2)-Pathologie des Zell-Clampings der Referenz.

**Zellgitter:** Zellgroesse **2h** (statt h in der Referenz) -> der
27er-Stencil erfasst den Kernel-Stuetzradius 2h exakt. Die Referenz mit
Zellgroesse h uebersieht Nachbarn zwischen 1.5h und 2h; das ist ein
gefundener Diskretisierungsfehler (Fix fuer v0.3b vorgesehen).

**Determinismus (K9):** Zellsortierung seriell in Indexreihenfolge,
Nachbarsummen in fester Reihenfolge, keine Float-Atomics -> zwei Laeufe
sind bit-identisch (`test_determinism`).

**float32 statt float64:** GPU-tauglich. Paritaetstests nutzen daher
Toleranzen (Hydrostatik 15 %), nicht Bit-Gleichheit.

## 5. Bekannte Einschraenkungen (v0.3a)

- Der Taichi-Kern wurde in der Entwicklungsumgebung nicht ausgefuehrt
  (kein taichi installierbar). Erste Ausfuehrung auf dem Zielrechner kann
  1-2 Korrekturrunden brauchen.
- `density_at`/`velocity_at`/`apply_body_force` laufen ueber Host-Transfer
  (NumPy) - fuer die Kopplung ausreichend, aber nicht GPU-resident.
- K7 (20.000 Partikel + 10 Koerper @ 30 FPS) ist mit v0.3a erreichbar,
  aber noch nicht auf Zielhardware vermessen.
- Der Stencil-Fix ist nur im Taichi-Kern umgesetzt; die NumPy-Referenz
  behaelt Zellgroesse h (Fix fuer v0.3b).
